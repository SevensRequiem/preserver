# preserver

Encrypted GitHub mirror bundles (age), encrypted local-folder archives, and signed public-archive mirroring to removable drives. Design: `docs/design.md`. Example config: `docs/config.example.toml`.

## Names and personal data

preserver is its own app: `~/.config/preserver` (`config.toml`, `personal/{identity.age,recipient.txt}`), `~/.local/state/preserver`, `~/.cache/preserver`, `$XDG_RUNTIME_DIR/preserver` and `preserver-<job>.lock`, units `preserver-*`, `<drive>/preserver/{github-repos-personal,local-personal,public,kit,.state}`. Windows: `%APPDATA%\preserver`, `%LOCALAPPDATA%\preserver`. Nothing from another tool is read or migrated. An existing key comes in with `init --import <identity.age>`; old backups restore from wherever they are, since `restore` takes a file path and looks for `identity.age` next to it. Nothing host-specific or personal (drive uuid, email, owners) goes in source or docs: it comes from `~/.config/preserver/config.toml`; only `restore` runs without it.

## Layout

One package: `src/lib.rs` holds the logic, `src/main.rs` stays thin. Modules follow section 3 of `docs/design.md`. No platform trait: `src/platform/{linux,windows}/` export identical free functions under `cfg`.

## Build and gates

```
~/.claude/bin/cap ~/.claude/bin/ctrim cargo build -j N
~/.claude/bin/cap ~/.claude/bin/ctrim cargo clippy --all-targets --all-features -- -D warnings
~/.claude/bin/cap ~/.claude/bin/ctrim cargo test
cargo fmt --check
cargo deny check
```

N is 90% of cores. In the Claude sandbox set `CARGO_HOME=$TMPDIR/cargo` and `CARGO_TARGET_DIR=$TMPDIR/target`. `rustup target add` (targets in `rust-toolchain.toml`) writes `~/.rustup`, so run it outside the sandbox. Linux musl and `x86_64-pc-windows-gnu` cross builds are configured in `.cargo/config.toml`; MSVC builds come from CI.

## Rules

- Sync only (std threads, `std::sync::mpsc`), no tokio.
- Add a crate only in the phase that uses it, at an exact `=` pin. `deny.toml` bans `cc` outside ring (re-add the blake3 wrapper when a phase pulls it in).
- A file becomes visible only after it verifies. The age recipient is read from the home config only.
- GitHub token never in argv, URL, log or file.
- A catalog source with a `todo` is disabled until the todo is resolved.
- The personal flow touches real credentials and FIDO keys: run it by hand, not from an automated session.

## Phase 1a notes

- `main.rs` dispatches on argv0: `preserver-ssh` (the ssh program gix runs, a symlink to the binary in `$XDG_RUNTIME_DIR/preserver/`; it execs ssh with `ControlMaster=no`, the ControlPath and options that leave it nothing to authenticate with first (`IdentityAgent=none`, `IdentityFile=none`, no password or keyboard-interactive), because `ControlMaster=no` still falls back to a connection of its own when the master died, and that must fail at once, not wait for a touch). The personal fetch runs on gix (`git/mirror.rs`): the lane's stop flag ends it, https sends the `gh` token only to github.com, and before each repo `ssh -O check` restarts an expired master (a failure is `NeedsTouch`). Windows runs the first `ssh.exe` on PATH (else System32's) directly, with no shim and no master.
- Library internals are `pub(crate)`; unit tests sit next to the code and `tests/cli.rs` drives the built binary. Only `cli` and `SHIM`/`shim_main` are public.
- A test must not check that a job lock is free again after dropping it: a child another test thread is spawning shares the flock until it execs.
- In the Claude sandbox cargo cannot run inside the repo (it walks up to an unreadable `~/.cargo/config.toml`): rsync the tree to `$TMPDIR/pbuild` and build there; `rustfmt --edition 2024 src/lib.rs src/main.rs tests/cli.rs` works in place. The system D-Bus is blocked there too, so `drives`, `open` and mounting are only verifiable outside it.

## Phase 1b notes

- `tray_model.rs` is the whole tray logic as a pure function (status files + lock state in, icon/tooltip/menu labels out). `platform/linux/tray.rs` only maps it onto ksni and owns one loop: menu clicks and helper threads send it a `Cmd`, it refreshes hourly, on every command and when the menu opens. ksni re-registers by itself when the watcher restarts (`service.rs`, `NameOwnerChanged`).
- The tray menu is `tray_model.rs`'s `Model` (`Inputs.starting` lists the commands the tray or GUI started that have not exited, so only their own entries grey out; the queue line counts `NeedsTouch` as "waiting for your key", not for the drive): one entry per command (`Command::{Personal, Local, Public, CopyRule}`: back up personal, local folders, mirror public sets, copy now per rule), the info lines (last backup, public, daemon, queue with byte totals), the pause item, a submenu per unfinished job (progress label, Cancel, Retry) and "Open preserver" (starts `preserver-gui` next to the binary, reaped on a thread, a notification when it is missing). A command goes through `actions::run`: queued for the daemon (then `queue/wake`) when it runs, else `preserver <args> --foreground` (`Command::args`, e.g. `copy --rule ID --foreground`) as a child the tray waits for on a thread: the exit status is the only sign of a run that died before writing its status file. `actions::snapshot` gathers the model's inputs. At start the tray imports DISPLAY, WAYLAND_DISPLAY and XAUTHORITY into the user manager, where the daemon reads them per job for the askpass dialog. A job `Blocked(NeedsTouch)` raises one notification per job id per tray process, with a "Back up now" button.
- The transport menu edits the `transport` line of `config.toml` in place (`config::with_transport`) and re-parses the result: every other setting must be unchanged or nothing is written. No TOML writer, so comments survive.
- Notifications go over zbus (`platform/linux/notify.rs`), no `notify-send`. The overdue reminder is shown once per day per tray process, not persisted.
- Local folders (`personal/local.rs`): tar on a thread -> pipe -> ruzstd -> age -> `.tmp`, fsync, rename, fsync dir. ruzstd only has its fastest level and unwraps I/O results, hence the `Held` adapters. Format details are in `docs/design.md` section 4.
- `restore` of a `Dnn` reads the `L0.tar.zst.age` next to it; of an `L0`, just that. An archive with no manifest (not written by preserver) is refused, and the error gives the GNU tar command.
- A month whose L0 has no `.idx` in the state dir makes `personal --local-only` fail for that folder until the month directory is moved aside or the month ends.
- The sandbox blocks unix sockets: the tray is checked outside it against a private `dbus-daemon --config-file` (no service dirs, or Notify hangs on activation) with HOME and XDG_RUNTIME_DIR in a scratch dir. Never test against the session bus.

## Phase 2 notes

- `net/`: `client.rs` (ureq agent, rustls+ring, roots from the OS via rustls-platform-verifier; `embedded_roots` is the webpki-roots fallback, `RootCerts::WebPki`, used when the platform verifier cannot load an OS store; ureq's `rustls-webpki-roots` feature brings the crate and a direct `=` line pins it, and `deny.toml` allows CDLA-Permissive-2.0 for that crate only), `throttle.rs` (one token bucket with debt, shared by every stream), `download.rs` (one Range/If-Range GET for the rest of the file per attempt, checkpointed every 64 MiB, or every 60 s on a slower stream, as it arrives: `.part` + `.part.json` sidecar holding the SHA-256/512 midstate), `hash.rs` (resumable SHA-2 on `sha2::compress*`).
- `queue/`: job JSON is written by the worker only; the CLI and tray write `<id>.ctl` / `all.ctl`, which the worker reads every second. One worker, under the `preserver-queue` lock, runs one job at a time in (priority, created) order; a job that sorts before the running one, once queued, makes it yield (`Halt::Yield`: back to Queued, partials kept, no attempt counted), so a long set such as `extras` cannot hold the next daily batch for days.
- The agent follows no redirects (`max_redirects(0)`): `Downloader::call` follows them, up to 10, so an error reads `<url> via <hop>: ...` with the hop that failed (its query left out). Each attempt goes through the redirects again, so a download host that picks a mirror per request can move a resume to another mirror; If-Range keeps that safe. Only one request per attempt, not one per checkpoint: a kiwix mirror stopped accepting connections after minutes of 64 MiB segments while curl from the same host still got through. Bodies' errors are prefixed in `transfer` (`Fail::at`), not in `copy`.
- A `.part` without a matching sidecar restarts from zero: nothing proves what its bytes are. A `200` to a ranged request that is longer than the bytes asked for is dropped and asked for again as a plain GET, so its timeout comes from the file size. A failed attempt that saved a checkpoint (a time checkpoint counts as progress) is `Fail::Retry { progressed: true }` and resets the file's count in `sched`: only `TRIES` attempts in a row without progress fail it. A failed `fetch` takes its bytes back off the shared progress counter (not a stop).
- Network tests use `net/testserver.rs` (in-process loopback HTTP) and `net/testdata/` (a test CA and leaf; `gen.sh` regenerates them). The per-host test binds 127.0.0.2, which Linux routes to loopback.
- ring needs a C cross compiler for the cross clippy gates. Without mingw or MSVC headers they pass with `CFLAGS=-DRING_CORE_NOSTDLIBINC`, `CC_<target>=clang`, `AR_<target>=ar`; for `aarch64-pc-windows-msvc` also `-D__GNUC__=4` in its CFLAGS and an AR that maps lib.exe arguments onto `ar crs`. Those objects are only for checking, never ship them.
- `catalog.toml` and `keys/*.gpg` are compiled in (`catalog.rs`, `keys.rs`). `keys/FINGERPRINTS` lists every primary key and a test holds it to what rpgp parses; `keys/fetch.sh` (needs gpg and curl, run by hand) fetches a missing keyring, never replaces one, and rewrites FINGERPRINTS. A new keyring also needs its line in `keys.rs`. The catalog refuses unknown fields, and a signed source whose keyring is not compiled in.
- `resolve/`: `Item` keeps hashes as the published hex, and the plan hash is built from it. No `url` crate: `listing.rs` joins hrefs itself.
- `verify/pgp.rs` replaces gpgv. Same verdicts as gpgv's zero-exit VALIDSIG (a test runs both when `/usr/bin/gpgv` exists): every signature in the file must verify, an expired key still counts, an expired signature or one older than its key does not. Stricter in one place: a revoked key or subkey is refused. Clearsigned sums are read from the signed text only. Two gnu-keyring keys (RSA 9888 and 15424 bit) are above rpgp's size limit without its `large-rsa` feature, so their signatures fail closed.
- `public/`: one queue job per set. The worker's `plan` resolves and stages (`.staging/<plan16>/`, hard links or copies from the newest version, signature and sums files as extra downloads); its `settle` hook verifies and renames the stage into place, or fails the job. A file that fails verification is deleted with its side files; the rest of the stage waits for the next run. `git` and `repo` sources are skipped until phase 3. Bytes already staged count against the budget, so a resumed job is not refused. A carried file never brings a side file that a changed file of the same source fetches fresh. `publish` deletes anything in the stage that is not a plan file or its side file, then `syncfs` before the rename (prune follows), since copies on FAT/exFAT are not otherwise flushed.
- Tests make OpenPGP keys with rpgp (`verify/testkey.rs`). The RNG trait comes from the `rsa` dev-dependency's `rand_core` re-export; `rsa` is also a normal dependency now (Alpine verify); the dev entry adds `getrandom`.
- `deny.toml`: `Zlib` is allowed for zlib-rs (pgp's flate2 backend); RUSTSEC-2023-0071 (rsa 0.9) is ignored because rsa only verifies here (public keys); private keys exist only in tests.
- `$TMPDIR` is a 16 GB tmpfs with a quota: a full `target/` makes tests fail with "Disk quota exceeded". Delete `target/debug/incremental` and build with `CARGO_INCREMENTAL=0`.

## Daemon notes

- `daemon.rs`: `preserver daemon` holds `preserver-daemon.lock` for life (a second one logs "waiting for the running daemon to exit" and blocks, so an overlapping restart is no crash loop) and writes `status/daemon.json` once. Main runs the event loop (schedules, copy rules, mounting a wanted drive on plug-in), one thread per lane runs passes, the udisks and queue watchers wake main (`Wake::{Drive, Queue}`). The CLI, tray and daemon share `actions.rs`: `daemon_live` (the lock), `wake` (`queue/wake`, which the inotify watch on the queue directory turns into a pass; `.ctl` writes wake it too), best-effort `mount`, `enqueue_personal`, `retry` and the CLI `handoff`. No socket: control stays `.ctl` in, job JSON and `status/*.json` out.
- Lanes: `JobKind::lane()`. A worker resets, applies controls to and writes only its own lane's jobs, so two lanes never write the same job file. `Lane::Download` runs under `preserver-queue.lock`, `Lane::Copy` under `preserver-copy-queue.lock`, `Lane::Personal` (GitHub and local jobs, `personal/lane.rs`) under `preserver-personal-queue.lock`, then `github`/`local` (`status::job`), so the status files keep their meaning.
- `Pass { retry_failed, retry_blocked }`: `FRESH` for CLI runs, `TICK` for the 30 s tick and queue wake-ups (requeues only crashed `Running` jobs), drive events and the hourly sweep also requeue `Blocked`, except `Blocked(NeedsTouch)`: only a ctl retry or the next scheduled occurrence asks for the key again, so the daemon never prompts in a loop. `runnable()` decides whether a pass would do anything, so an idle tick loads nothing and writes no status. Coalesced passes OR their flags.
- `daemon_pass` only `try_lock`s the queue: a CLI run already holding it wins and the daemon tries again next tick. Lock order is queue, then public (`status::job`). `Store::enqueue` keeps one unfinished job per kind (any GitHub job matches, whatever its transport) and bumps `retry` and clears `pause` in a stopped one's ctl; a retry requeues `Blocked` as well as `Failed`. `Store::retry` does not bump again while the lane has not applied an earlier retry (`retry > retry_seen`): every ctl write wakes the daemon, whose scheduler would otherwise ask again on each wake-up. `personal --transport T` is refused while a GitHub job queued over the other transport is unfinished.
- The watcher is one `MessageIterator` with one match rule (udisks signals under `/org/freedesktop/UDisks2`, turned into `DriveEvent`s by `drive_event`); it reconnects every 30 s and warns once per failure streak. A signal with a destination (sent to this connection, not broadcast) is dropped: the bus checks the rule's sender on broadcasts only. Its end-to-end test runs only outside the sandbox against a private bus: `PRESERVER_DBUS_TEST=1` on the test binary with `DBUS_SESSION_BUS_ADDRESS` and `DBUS_SYSTEM_BUS_ADDRESS` unset, filter `watcher_sees_a_plug_in`.
- The tray shows the daemon and queue lines and a pause item (writes `all.ctl`), and polls every 5 s while a job runs, 60 s while one waits, hourly otherwise.
- Lanes never mount (`platform::locate`: Absent and Unmounted are `Blocked` without an attempt). Only people's actions mount, and the daemon's `mount_added` on InterfacesAdded for a wanted id (primary, copy rule or unfinished copy job targets); a drive already plugged in when the daemon starts stays "not mounted" until someone mounts it, replugs it or presses Retry. Mounting from the user service goes through polkit with `auth.no_user_interaction`; not yet checked on a real session.
- Schedules: `[schedule]` in config.toml (`personal` = the GitHub job, `local`, `public`; `H:MM:SS` every, `HH:MM` daily) go through `schedule::tick` before every pass; `copy::rules::due` uses the same `schedule::due`. `last_run` from `status/<job>.json` is the memory, so a missed occurrence runs once and a manual run counts. A Failed or `NeedsTouch` job older than the occurrence gets one ctl retry. `public` is due from the later of its `last_run` and the time this daemon last queued it (in memory), and then queues every catalog set except a Paused one, retrying the stopped ones. A canceled GitHub or local job writes `last_run` (not `last_ok`) to its status file, so the schedule does not queue it again at once.
- The personal lane gets the session's DISPLAY, WAYLAND_DISPLAY, XAUTHORITY and SSH_AUTH_SOCK from `systemctl --user show-environment` per job (5 s bound). ssh over the FIDO key waits 120 s for the touch (`TOUCH_WAIT`), in its own process group so a timeout or a pause ends the askpass too; on a terminal (a foreground run) it keeps the terminal's group so a PIN prompt there works. No answer, or ssh with no graphical session, is `Blocked(NeedsTouch)`. Windows has no drive events yet (`watch_drives` warns), and restart-on-failure for the `\preserver\daemon` task XML is phase 5.
- The AR wrapper for the `aarch64-pc-windows-msvc` clippy gate must accept lowercase `-out:` too: cc-rs passes that form.

## Copy notes

- `copy/`: `plan.rs` is pure (inputs in, `Plan` out, unit-tested at 16G/32G/128G/2T and shrinking); `exec.rs` writes (stage, read back, rename); `rules.rs` owns `copy.toml`; `mod.rs` scans both trees, runs a job, and is the lane, the scheduler and the CLI. Design in `docs/design.md` §3.6.
- The lane's lock order is `copy-queue`, then `copy` (`status::job`). `record` writes `status/copy.json` (one `sets` entry per rule, or `once-<target id>` for one-off copies) before it removes Done and Canceled jobs: `schedule` reads the last run from there, so a rule never looks as if it never ran.
- A job runs `execute` on a scoped thread; the lane thread polls the job's ctl every second and sets `Prog::stop`, which `copy_file` checks per 1 MiB chunk. A run that finds the primary pruned under it (`Vanished`) plans once more. A missing primary or target is `Blocked` without an attempt.
- `.state/copy.json` on the target marks the tree as a copy's (and holds the personal size/mtime and kit fingerprint); without it a non-empty `preserver/` is refused. It is written before anything else so an interrupted first run resumes.
- The Env seam (`drive`, `fstype`, `free`, `cluster`, `say`) lets the end-to-end tests in `copy/tests.rs` fake both drives in a temp dir; nothing there touches udisks. The `public --list` CLI test points `DBUS_SYSTEM_BUS_ADDRESS` at a missing socket for the same reason.
- clippy's `allow-unwrap-in-tests` only recognizes a literal `#[cfg(test)]` on the module: gate a unix-only test file with `#![cfg(unix)]` inside it, not `#[cfg(all(test, unix))]`.
- Anything read from the target's metadata (`copy.json`, `SET.toml`, `SHA256SUMS`, `MIRRORS.toml`) goes through `read_meta`: no links, no FIFOs, 32 MiB cap. A personal file the target cannot hold (FAT32 size, Windows names) fails the job after the rest is copied; a skipped public file is only a warning. A file reused from the old version is hashed again before the new `SHA256SUMS` lists it; an in-place replacement deletes the old files it will not reuse before copying.
- Not done: Windows `fs_type`/`block_size` return Unsupported (the drive's udisks/volume fstype is used first, else the copy is planned as "other"); a canceled job that never ran leaves an old stage until the next copy to that target clears it; an interrupted in-place replacement (no room for both versions) leaves that set absent until the next run.

## GUI notes

- `preserver-gui` (`src/bin/preserver-gui.rs`, feature `gui`, logic in `src/gui/`) is eframe 0.37 on glow: pages Status, Actions, Settings, Copy rules, Public sets. Every button calls what the tray or CLI calls (`actions::run`/`cancel`/`retry`/`pause_all`/`open_archive`, `config::save_transport`, `copy::{resolve, plan_text, save_rule, remove}`, `public::list_report`, `config_edit::save`); nothing in `gui/` writes state of its own. Long work (udisks, mounts, plans, child runs) goes to a std thread that sends a `Done` and wakes the window. It re-reads at `tray_model::refresh_interval`: 1 s while a job runs, 5 s while one waits, 60 s otherwise. A command started from the GUI runs the sibling `preserver` binary (`actions::preserver_exe`), not itself; so does a tray whose binary an upgrade replaced (`/proc/self/exe` then ends in " (deleted)"). On Windows the child gets `CREATE_NO_WINDOW`.
- Settings go through `config_edit.rs`: targeted line edits (`Place`, `Edit`), then the proof that the new text parses to exactly the old table with the edit applied, and still loads as a `Config`; otherwise nothing is written. Comments and order survive. `with_transport` uses the same path. A primary drive change needs a confirm tick. A schedule whose text is not of its radio button's kind is refused before saving. Every config.toml writer (`config::rewrite`) holds `preserver-config.lock` and writes through the symlink if config.toml is one; the Settings page saves only if the file still reads as the form it loaded.
- Linux: winit's `wayland-dlopen` and glutin's EGL/GLX loading keep the binary free of NEEDED display libraries (release CI fails on any); the GUI is a glibc build because musl static binaries cannot dlopen. It built here without any display -dev packages; the first CI run on ubuntu confirms that.
- egui's bundled fonts (Hack-Regular, Ubuntu-Light, egui-icons; NotoEmoji only with `monochrome_emoji_fonts`, which is off) are covered by the `deny.toml` exception for `epaint_default_fonts`; their texts and Ubuntu-Light's copyright notice ship in `dist/licenses/`.
- Never launched in an automated session: the sandbox has no display. Status/Settings/Copy logic is unit-tested as plain functions (`drive_choices`, `fraction`, `Draft`/`edits`, `tokens`).

## Phase 3 notes

- Queue work (`queue/sched.rs`): a planner returns `Work::Fetch(Planned { fetches, more, whole })` or `Work::Run`. `From<Vec<Fetch>>` builds the plain batch. The planner gets `ok`, the indices of the previous batch that verified, and only those reach `done.tsv`. `more` with no fetches fails the job ("planner returned an empty batch"). Halt is re-checked between batches. `outranked` yields only `Work::Fetch` jobs: a `Work::Run` (a git transfer, which has no resume) is never yielded, and pause and cancel still stop it through its stop flag.
- `JobKind::Mirror { set, source }` is in `Lane::Download`, one job per enabled in-place source (`git` or `repo`). `public::enqueue_all` queues a set job only for sets with a versioned source. Each mirror result is a `status/public.json` `sets` entry named `<set>/<source>`.
- In-place trees keep bookkeeping in `<tree>/.preserver/`: `live.tsv` (the visible payload), `done.tsv` (one line per fetch the pool reported verified), `want.tsv` (rebuilt every run, never a resume shortcut), `swap.json` (the swap journal, removed last) and `staging/<gen16>/{meta,incoming,old,live.tsv}` (`old` holds what the swap replaces). Trees live at `public/<set>/<source>/` (repo) and `public/<set>/git/<source>.git` (git). Metadata is checked against the anchor on every run. A present file with no `done.tsv` line is hashed again before it is trusted (`Have::Suspect`).
- Swap (`generation.rs`): `platform::exchange` (`renameat2` `RENAME_EXCHANGE` on Linux) when it reports support. Where it returns `Ok(false)` (always on Windows) the old tree is renamed aside and the new one renamed in. `swap.json` is written on every OS.
- Alpine apks: `Expect::Apk` is verified in `Downloader` finish, where the whole `.part` is re-read even when resumed, since the sidecar midstate only covers SHA-256. There is no apk branch in `generation.rs`.
- Fedora: the primary must be `.xml.zst`, anything else fails closed. A new repomd needs a `<revision>` above the live one (`fedora.rs`), and a metalink `mm0:timestamp` older than the one in `live.tsv`'s `anchor_ts` header is refused.
- `pgp::release` (`verify/pgp.rs`) checks a clearsigned Release. A signature by a key outside the ring is ignored. A signature that names a ring key must verify, and at least one must. The issuer is matched by the hashed issuer fingerprint, with the key ID as a fallback only. A subkey counts only with a valid signing binding.
- Key pinning: catalog `signers` are fingerprints, and a Debian source needs both `keyring` and `signers` (`catalog.rs`). Each Debian signer must be listed in its keyring (`keys::listed`). `Signer::pinned` accepts any ring key when the list is empty, so pin every signed source that has one.
- Catalog: a source with a `todo` must be disabled, and an enabled source with a `todo` is refused (`catalog.rs:229-235`). Every enabled source URL must be https, git included.
- gix HTTP (`git/http.rs`): the transport runs in-process on the shared ureq agent and throttle. It follows no redirects. Errors name the status and the URL without its query, never header lines. The POST body is capped at 16 MiB. The `parallel` feature is off, and `http-client-insecure-credentials` is never enabled.
- Git packs (`git/mirror.rs`): every pack not listed in `preserver-checked` is verified before publish. That list lives on the drive and has the same trust as the packs. Progress reads "checking pack i/n".
- `git/testcgi.rs` is `#![cfg(unix)]`. It serves https on loopback through `git http-backend`, with the test CA and leaf in `net/testdata/`.

## Bandwidth notes

- `Throttle` keeps its rate inside the bucket mutex. `set_mbit` settles the bucket at the old rate first, so debt carries over in bytes; a switch to or from 0 restarts the bucket empty, since unlimited bytes were never charged.
- `public::Limit::refresh` (called through `Worker.limit` before each job and on every 1 s tick of `batch` and `run_closure`) re-reads `config.toml` only when its mtime or length changes, keeps the last good config when a new one fails to parse, and sets the rate from `Config::mbit_at(now)`: first covering `bandwidth_windows` entry, else `bandwidth_mbit`. `Window::covers` puts a wrapping window (or `from == to`, a whole day) on the day it opens for `days`. The personal lane stays unthrottled and dry runs never call `take`. The Settings page edits the list through `config_edit` (one line, comments inside it lost); it only handles the inline array, so a hand-written `[[bandwidth_windows]]` table list makes its save fail the parse proof and nothing is written.
- No override, tray label or CLI for the limit: only home `config.toml` decides it.

## Install and release

- `./install.sh` builds this checkout (`cargo build --release --locked --features gui`) and installs; `./install.sh DIR` installs from a downloaded release dir (`preserver-<target>` + `SHA256SUMS`), checking the host target's hash with `sha256sum -c` on the staged copy and refusing on a mismatch. Binary goes to `~/.local/bin/preserver` by atomic rename, the one it replaces is kept as `preserver.prev`. A release's `preserver-gui-<arch>-unknown-linux-gnu` is installed the same way (`preserver-gui.prev`) when the release has it and `getconf GNU_LIBC_VERSION` succeeds; both hashes are checked before either is installed, and a release without it leaves an installed GUI alone. Checkout mode builds `--features gui`. The GUI also gets `${XDG_DATA_HOME:-~/.local/share}/applications/preserver.desktop` with an absolute, quoted Exec; a bindir with `"`, `` ` ``, `$`, `\`, `%` or a newline is refused up front. Units in `dist/systemd/` are copied (not linked) to `~/.config/systemd/user`: the tray and `preserver-daemon.service` (started at once, try-restarted on upgrade and rollback), both enabled. Job times live in `[schedule]` in config.toml, run by the daemon. The retired `preserver-{personal,local,public}.service` and `preserver-{local,public}.timer` are disabled and stopped one unit per `systemctl` call (systemd fails the whole call on a missing unit file) and removed on install (with a hint to set `local` under `[schedule]` when the local timer was on), and removed by `--uninstall` too. The installer imports whichever of DISPLAY, WAYLAND_DISPLAY and XAUTHORITY it has into the user manager. The daemon unit has no `PrivateTmp` (the askpass needs `/tmp/.X11-unix`) and defaults `SSH_AUTH_SOCK` to `%t/ssh-agent.socket`. `--rollback` swaps each pair whose `.prev` exists (run it again to swap forward); an install that replaces only one of the two binaries deletes the other's older `.prev`, so a rollback undoes exactly the last install; `--uninstall` removes both binaries, their `.prev`, the desktop file and units and never touches config, keys, state or backups.
- `install.bat` does the same on Windows (`certutil` hash check in `:verify` for both exes before either is installed, `%LOCALAPPDATA%\preserver\bin`, `preserver.prev.exe` and `preserver-gui.prev.exe`, `/rollback`, `/uninstall`, a Start Menu shortcut made by PowerShell with the paths passed through the environment) and registers `\preserver\{tray,daemon}` through `schtasks /XML` itself, because the binary's `install` subcommand is still a phase 5 stub, and ends and deletes the retired `\preserver\{local,public}`; `/uninstall` removes all four. It has not been run on Windows yet.
- `tests/install-sh.sh` drives `install.sh` in a scratch HOME with fake `systemctl`, `cargo` and `getconf` (`FAKE_MUSL=1` plays a host without glibc); CI runs it.
- Releases: push a `v*` tag matching the `Cargo.toml` version. `.github/workflows/release.yml` builds `preserver-<target>[.exe]` for x86_64/aarch64 linux-musl and windows-msvc, `preserver-gui-<target>` for x86_64/aarch64 linux-gnu (with a `readelf -d` check) and `preserver-gui-<target>.exe` for windows-msvc, writes `SHA256SUMS` and attaches both to the GitHub release. `ci.yml` runs fmt, clippy, test (with and without `--features gui`), `cargo deny` and the install test on Linux, build and test with `--features gui` on Windows x64 and ARM64. Actions are pinned by commit SHA with the version in a comment.
